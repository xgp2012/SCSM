### 3.2 配置快照接口

`GET /api/instances/:id/config` 返回 6 个分区及分区元数据：

```
sections = settings, serverSetting, level, ban, limit, password
meta     = [settings(effective,writableRunning), serverSetting(effective),
            level(effective), ban(effective), limit(legacy), password(legacy)]
```

- `settings`：`Settings.xml` 的 `{Name: Value}`。
- `serverSetting`：`ServerSetting.json` 解析结果；`WorldPassword` 回显为 `********`（`SECRET_PLACEHOLDER`）。
- `password`：`DefaultPassword` 与各 `PlayerPassword` 值回显为 `********`。
- `limit`/`password` 标记 `effective=false`（编译产物未发现，见 §4）。

### 3.3 权限 / 封禁 / 限制 写入与未知字段保留

写入前读取原始文件，写入后重读并比对：

```
权限：LevelConfig.json = {"Alice":100,"Bob":50}         ← 新增两条
封禁：BanConfig.json   = {"BanUserList":["Eve"],...}     ← 新增 Eve，Unknown:7 保留
限制：LimitConfig.json = {"WaterLength":9,...}           ← 修改，CustomField:"keep" 保留
```

**未知字段/未管理条目均未被破坏**（`Unknown` / `CustomField` 原样保留）。

### 3.4 密码写入与脱敏往返

```
PUT .../config/password  { IsUse:true, DefaultPassword:"pw-123", PlayerPassword:{Alice:"alice-pw"} }
→ Plugins/Password.json = {"IsUse":true,"DefaultPassword":"pw-123","PlayerPassword":{"Alice":"alice-pw"}}
```

- 读取时脱敏为 `********`；提交 `********` 表示保持原值（单元测试 `server-config.test.ts` 覆盖）。

### 3.5 世界参数写入 Settings.xml / ServerSetting.json

```
PATCH /instances/:id { serverPort:28941, maxPlayers:33, autoRun:true, gameMode:2 }
→ Settings.xml      Name="ServerPort" Value="28941"
→ ServerSetting.json WorldMaxPlayers=33, Autorun=true, GameMode=2
```

### 3.6 重启后读取新配置（探测核实）

```
POST /instances/:id/start
[Supervisor] 服务端开启成功，端口 28941
[Supervisor] status → running
独立 UDP 探测 28941 → online=true version=x26.06.19（新端口真实监听）
```

服务端经**新端口 28941** 监听并响应探测，证明重启后确实读取了新的 `ServerPort`。

> **实测发现（重要）**：探测回执中的 `maxCount` 来自**世界数据**
> `WorldSettings.MaxOnlinePlayerCount`（世界 `Project.json` / MessagePack），而**非**
> `ServerSetting.json.WorldMaxPlayers`。`WorldMaxPlayers` 仅在**新建世界**
> (`AutoGenerateWorld=true`) 时作为播种值；对已存在的世界，修改它不会改变实际上限。
> 因此本条以「文件落盘 + 新端口探测响应」作为服务端读取新配置的核实方式；
> `maxCount` 与 `WorldMaxPlayers` 的一致性仅在首建世界时成立（M3 报告即此种情形，模板世界恰好为 20）。

### 3.7 非法输入被拒绝

```
PUT .../config/level  {"X":-1}          → 400 玩家 X 的等级必须是非负整数
PUT .../config/ban    {"BanUserList":"oops"} → 400 BanUserList 必须是字符串数组
PUT .../config/nope   {"a":1}           → 400 不支持的分区: nope
```

统一错误包络（`AllExceptionsFilter`）返回 `{ ok:false, statusCode, message }`，消息可读。

### 3.8 运行中写保护

```
实例 running 时：
PUT .../config/level → 409 玩家权限（Configs/LevelConfig.json）在实例运行中不可修改，请先停止实例
```

- `Settings.xml`（`writableWhileRunning=true`）允许热改 `ServerPort` 等；
- 世界参数/权限/封禁/密码/限制分区运行中禁止写入（返回 409）。

## 7. 已知项 / 后续（M5 起）

- **`WorldMaxPlayers` 生效口径**：仅对**新建世界**生效；已存在世界的实际上限在
  世界数据（`WorldSettings.MaxOnlinePlayerCount`）内。M5+ 如需改存量世界上限，
  可在停止实例后解析/改写世界 `Project.json`（MessagePack），或经控制台命令。
- **密码/限制插件未编译**：当前编译版服务端不消费 `Plugins/Password.json`。
  面板保留文件管理并标注；运行时可经控制台命令（`/paw` 等，若可用）即时生效。
- **HMRL 语义**：`WorldPassword` 同 `WorldMaxPlayers`，为世界级参数，实际校验值取自世界数据；
  M5 备份/恢复流程将与世界数据一并处理。
- **审计**：M4 配置写入暂未写审计日志（`AuditLog`），归 M7 安全阶段统一接入。
