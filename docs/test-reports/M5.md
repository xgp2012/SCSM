### 3.2 列出真实存档

`GET /api/instances/:id/worlds` 解析实例目录 `Worlds/`，返回世界名、路径、大小、文件数、
最近修改、是否当前世界（对齐 `ServerSetting.json.WorldPath`）与是否含 `Project.json`：

```
worlds=World current=World files=2 size=6204
```

### 3.3 备份落盘

`POST /api/instances/:id/backups { world, includeConfig:true }` 生成
`backups/<uuid>.tar.gz` 与同名 `<uuid>.json` 元数据（原子写）：

```
file=b16554a3-d341-4406-afd5-52e32a93ea2d.tar.gz size=3908B type=manual includes={"world":true,"config":true}
```

元数据 `size` 与实际归档字节一致（`b1.size === statSync(archive).size`）。

### 3.4 归档内容与一致性

门禁把 `Worlds/World/Project.json` 中的版本号 `"2.4"` 篡改为 `"9.9"`（模拟误操作），
随后从备份恢复。

### 3.5 恢复备份（含预恢复快照）→ 数据还原 + 可启动

```
恢复备份后世界数据还原且生成预恢复快照 | snapshot=633d2a3d-... equalBaseline=true
恢复后服务端可正常加载存档启动 | status=running port=28950 pid=7260
```

- 恢复流程：运行中先 `stop` → 生成 `pre-restore` 安全快照 → 解压覆盖。
- 恢复后 `Project.json` 与备份前逐字节一致（`equalBaseline=true`）。
- **真实启动服务端**并进入 `running`，证明服务端可正常加载该存档（门禁第 3 条核心）。

### 3.6 运行中写保护

```
POST /instances/:id/backups（实例 running）→ 409
```

运行中禁止备份，避免世界数据快照撕裂。

### 3.7 定时备份（短周期）

以 `BACKUP_INTERVAL_MS=15000` 启动，创建实例后等待，`GET :id/backups` 返回按 15s 间隔
自动产生的 `auto` 备份：

```
[Backup] 定时备份 15000ms 已启动（保留 10）
{"type":"auto","note":"定时自动备份","createdAt":"...:52:14"}  ← 15s
{"type":"auto","note":"定时自动备份","createdAt":"...:52:29"}  ← 30s
{"type":"auto","note":"定时自动备份","createdAt":"...:52:44"}  ← 45s
```

定时任务仅对 **stopped** 且存在当前世界目录的实例执行（单元测试覆盖运行中跳过）。

### 3.8 删除与保留

- `DELETE /instances/:id/backups/:backupId` 同时移除归档与元数据（`archiveGone=true`）。
- 保留策略 `BACKUP_KEEP`（默认 10）：超出按时间从旧到新淘汰，`pre-restore` 快照优先保留。

## 5. 交付物（M5）

- **共享类型（packages/shared/src/backup.ts，新）**：
  `BackupType` / `BackupIncludes` / `BackupMeta` / `WorldInfo` /
  `CreateBackupInput` / `RestoreBackupInput`；并入 `index.ts` 导出。
- **后端（apps/api）**：
  - `backup/archive.ts`（新）：基于 `tar` 的**流式** tar.gz 打包/解包
    （`portable:true`，POSIX 路径，低内存）。
  - `backup/backup.service.ts`（新）：列存档（递归统计大小/文件数）、创建备份
    （世界+配置）、恢复（停止→预快照→解压覆盖）、删除、保留淘汰、定时任务
    （`OnModuleInit` + `setInterval`）、路径越界防护、原子写元数据。
  - `backup/backup.controller.ts`（新）：`GET :id/worlds`、`GET/POST :id/backups`、
    `POST :id/backups/:backupId/restore`、`GET .../download`、`DELETE .../:backupId`。
  - `backup/backup.module.ts`（新）；`app.module.ts` 注册（置于 `InstanceModule` 之前，
    避免 `:id/:action` 生命周期路由吞噬 `/backups`）。
  - `config/env.ts`：新增 `BACKUP_INTERVAL_MS`（0=禁用）/`BACKUP_KEEP`（默认 10）。
  - 依赖：新增 `tar@^7.5.22`（流式，M6 版本包解压可复用）。
- **前端（apps/web）**：
  - `components/instance/BackupPanel.vue`（新）：世界存档表、创建备份（世界+配置选项、
    运行中禁用）、备份列表（类型徽标/下载/恢复/删除）、恢复前快照说明。
  - `pages/instances/[id].vue`：「存档与备份」标签接入 `BackupPanel`（替换 M5 占位）。
- **运维**：`apps/api/scripts/m5-gate.cjs`（门禁脚本）、`docs/test-reports/M5.md`（本文件）。

## 6. 已知项 / 后续（M6 起）

- **恢复语义**：当前为「解压覆盖」世界与配置目录（同名文件覆盖，未知配置不删除）。
  若需「清空后精确还原」可在 M7 增加可选严格模式。
- **运行中备份被禁止**：以一致性为先；如需热备需服务端侧保存机制（`/save`）配合，留待 M7 评估。
- **原生 `/backup`**：编译产物未含该命令实现，M5 采用面板侧文件级备份（用户决策）；
  后续如服务端提供保存命令，可在备份前经 PTY 发送以确保世界数据落盘。
- **下载鉴权**：下载端点复用 HttpOnly Cookie 守卫；大归档目前整文件流式输出（未做断点续传）。
